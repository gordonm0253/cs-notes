Network Flow

Introduction​

Many optimization problems reduce to routing as much "stuff" as possible through a network subject to capacity limits, such as traffic through roads, data through pipes, and goods through supply chains. Network flow formalizes this and gives efficient algorithms with broad applications (e.g. bipartite matching).

The central problem: given a directed graph with edge capacities, a source and sink node, find the maximum amount of flow that can be routed from source to sink without violating any capacity or conservation constraints.

Definitions​

Flow Network. A flow network is a directed graph G=(V,E)G = (V, E)G=(V,E) where each edge e∈Ee \in Ee∈E has capacity ce≥0c_e \ge 0ce​≥0, a source node s∈Vs \in Vs∈V and sink node t∈Vt \in Vt∈V. We assume no edge enters sss and no edge leaves ttt.

Flow. A flow is a function f:E→R≥0f: E \rightarrow \mathbb{R}_{\ge 0}f:E→R≥0​ satisfiying the following two conditions:

  • Capacity constraint. For every edge e∈Ee \in Ee∈E: f(e)≤cef(e) \le c_ef(e)≤ce​.
  • Conservation constraint. For every node v∈V∖{s,t}v \in V \setminus \{s, t\}v∈V∖{s,t}:
∑e into vf(e)=∑e out of vf(e)\begin{align*} \sum_{e \text{ into } v} f(e) = \sum_{e \text{ out of } v} f(e) \end{align*}e into v∑​f(e)=e out of v∑​f(e)​

That is, the flow in equals flow out at every internal node.

Value of a flow. The value of a flow is the total flow leaving the source:

value(f)=∑e out of sf(e)\begin{align*} \text{value}(f)= \sum_{e \text{ out of } s} f(e) \end{align*}value(f)=e out of s∑​f(e)​

Maximum flow problem. Given a flow network (G,c,s,t)(G, c, s, t)(G,c,s,t), find a flow fff maximizing ∣f∣|f|∣f∣.

Residual graph. Given a flow fff, the residual graph Gf=(V,Ef)G_f = (V, E_f)Gf​=(V,Ef​) captures remaining capacity. For each edge (u,v)∈E(u, v) \in E(u,v)∈E.

  • Add a forward edge (u,v)(u, v)(u,v) with residual capacity ce−fec_e - f_ece​−fe​ if e=(v,w)e = (v, w)e=(v,w) and fe<cef_e < c_efe​<ce​.

These backward edges allow us to "cancel" or undo any previously routed flow.

Augmenting path. An augmenting path is any path from sss to ttt in the residual graph GfG_fGf​. We say the bottleneck capacity of path PPP is:

bottleneck(P)=min⁡(min⁡forward e∈P(ce−fe),min⁡backward e∈Pfe).\begin{align*} \text{bottleneck}(P) = \min( \min_{\text{forward } e \in P} (c_e - f_e), \min_{\text{backward } e \in P} f_e). \end{align*}bottleneck(P)=min(forward e∈Pmin​(ce​−fe​),backward e∈Pmin​fe​).​

In other words, it is the maximum flow we can add/subtract onto any foward/backward edge along PPP without violating any capacity constraints (without exceed cec_ece​ or going below 0).

Ford-Fulkerson​

Ford-Fulkerson repeatedly finds an augmenting path in the residual graph GfG_fGf​ and pushes flow along it equal to its bottleneck capacity, until no augmenting path remains. After finding an augmenting path PPP with flow fff and bottleneck bbb, we use the following augment operation.

  • For each forward edge e∈Pe \in Pe∈P: set f(e)←f(e)+bf(e) \leftarrow f(e) + bf(e)←f(e)+b.
  • For each backward edge e∈Pe \in Pe∈P (reversing an original edge e′∈Ee' \in Ee′∈E): set f(e′)←f(e′)−bf(e') \leftarrow f(e') - bf(e′)←f(e′)−b.

Algorithm​

Ford-Fulkerson(G, s, t, c):
    f(e) = 0 for all edges
    build residual graph G_f
    while there is an s-t path P in G_f:
        b = bottleneck(P)
        f = augment(f, P, b)
        update G_f
    return flow f

Runtime Analysis. Suppose for flow network graph G=(V,E)G = (V, E)G=(V,E), let m=∣E∣m = |E|m=∣E∣. We can find augmenting paths in O(m)O(m)O(m) time and augments in O(n)O(n)O(n) time (each path has at most nnn nodes). This gives O(mC)O(mC)O(mC) time overall, since the loop can run at most CCC times. This is only pseudo-polynomial: the runtime depends on the capacities, not just on nnn and mmm.

Since the algorithm doesn't specify which augmenting path to pick at each step, a poor choice of paths can be extremely slow. Consider a network where an internal edge has capacity 1 but every other edge has a much larger capacity CCC. If Ford-Fulkerson happens to alternate between two augmenting paths that both route through this narrow edge, forward through it in one path and backward (canceling flow) in the next, each round trip only increases the total flow by 1, even though a smarter choice of paths would saturate the network in just two augmentations.
