Greedy Algorithms

Introduction​

Greedy algorithms build up a solution piece-by-piece, taking locally optimal choices at each step (without reconsidering past choices). For certain problems, locally optimal choices result in a globally optimal solution; in others, they produce a near-optimal one (see approximation algorithms). In this section, we explore greedy algorithms that produce an optimal solution, as well as two styles of correctness proofs for greedy algorithms: an exchange argument or a greedy stays ahead argument.

Proof Strategies​

Greedy Stays Ahead​

A greedy stays ahead argument shows that your greedy solution maintains some property that is "more extreme" than any other optimal solution at every step, and that this implies optimality. The general structure is:

  1. Find a property of your greedy solution that is "more extreme" (e.g., smaller or larger) than any other solution after each step (this usually relates to your greedy criterion).
  2. Make sure that extremity of this characteristic implies optimality.
  3. Prove via induction that the greedy solution actually maintains this property at every step.
  4. Conclude that your solution is as good as optimal.
note

It is very important that you explain why your property implies optimality! A common mistake is to identify a property that greedy maintains without connecting it to the size or quality of the final solution. The property alone means nothing; you need to argue that if greedy stays ahead in this metric, it must produce a solution at least as good as any optimal solution.

Exchange Argument​

Suppose that our greedy algorithm produces a solution AAA. Our goal with using an exchange argument is to prove that anything in an optimal solution OOO can be swapped with anything in our solution AAA without losing optimality.

  1. Assume that your greedy solution and the optimal solution you choose differ in some way. (If this is not the case, then A=OA = OA=O and we are done!).
  2. Show that it is possible to make progress, that is “exchange” elements in OOO to make it more similar to your solution AAA while preserving the optimality of OOO.
  3. Show that this exchange progress terminates, and when it does A=OA = OA=O where OOO is optimal. Then, AAA is at least as good as OOO, so AAA is optimal.
note

Make sure you exchange elements from OOO, not AAA! If you exchange elements from AAA, then you change the solution that you trying to prove is optimal!

Sample Problem: Interval Scheduling​

Suppose we have a machine MMM that can process at most 111 job at a time. We have nnn job requests, each with a start time sis_isi​ and end time fif_ifi​ for 1≤i≤n1 \le i \le n1≤i≤n with si<fis_i < f_isi​<fi​. Our objective is to schedule the maximum number of non-conflicting jobs. Formally, we want to maximize the size of the set of non-conflicting jobs S⊆[n]S \subseteq [n]S⊆[n] that we want to schedule on MMM. We say two jobs iii and jjj are non-conflicting if:

  • job iii happens before job jjj: si≤fi≤sj≤fjs_i \le f_i \le s_j \le f_jsi​≤fi​≤sj​≤fj​
  • job jjj happens before job iii: sj≤fj≤si≤fis_j \le f_j \le s_i \le f_isj​≤fj​≤si​≤fi​

Give an efficient algorithm that solves this problem.

Solution​

To solve this problem, we want to pick the jobs with the earliest remaining finish times. This way, we leave the most remaining time for future jobs, maximizing our future options.

R = set of all jobs, A = []
while R is not empty:
    pick job i in R with the earliest remaining finish time and add it to A
    remove all jobs in R that conflict with i
output A

Before we prove this solution, it is a good exercise is to try and disprove bad greedy strategies. Can you find a counterexample for the following greedy approaches? For each approach, you can assume that after a job is selected, you remove all jobs that conflict with it.

  • Select the remaining job with the earliest start time.

Suppose we had 3 jobs.

  • Job 3: s3=4s_3 = 4s3​=4, f3=5f_3 = 5f3​=5

With our earliest start time strategy, we take job 1, which conflicts with both other remaining jobs. The optimal solution involves taking jobs 2 and 3 (which don't overlap). Therefore, this straetgy is not optimal.

  • Select the remaining job with the shortest interval (the one that minimizes fi−sif_i - s_ifi​−si​).
Solution

Consider the following set of 3 jobs.

  • Job 1: s1=1s_1 = 1s1​=1, f1=5f_1 = 5f1​=5
  • Job 2: s2=4s_2 = 4s2​=4, f2=7f_2 = 7f2​=7

We can prove that our strategy of picking the earliest remaining finish time is optimal strategy. We show this using both greedy-stays-ahead and exchange argument proofs. For a problem set or exam, you'll only need to select one proof style, so be sure to pick the proof style that is the most straightforward!

Runtime Analysis​

We can make our algorithm run in O(nlog⁡n)O(n \log n)O(nlogn) time. We first sort the nnn jobs in order of finishing time in O(nlog⁡n)O(n \log n)O(nlogn) time. We select jobs by processing the intervals in this sorted order, maintaining the finish time of the most recently selected job; for each job, we check whether its start time is at least this finish time, which takes O(1)O(1)O(1) time per job, giving O(n)O(n)O(n) total. The overall runtime is dominated by the sort, so the algorithm runs in O(nlog⁡n)O(n \log n)O(nlogn) time.

Minimum Spanning Tree​

Suppose we have an connected, undirected graph G=(V,E)G = (V, E)G=(V,E), where edge e∈Ee \in Ee∈E has some positive edge weight cec_ece​. We want to find the a subset of the edges T⊆ET \subseteq ET⊆E such that the graph (V,T)(V, T)(V,T) is still connected and the sum of edge costs ∑e∈Tce\sum_{e \in T} c_e∑e∈T​ce​ is minimized. We call TTT the minimum spanning tree of our graph GGG.

For example, suppose we have a graph:

Can you identify the minimum spanning tree?

Solution

One spanning tree is {AB,BC,BD}\{AB, BC, BD\}{AB,BC,BD}, which connects all four vertices with total cost 1+2+4=71 + 2 + 4 = 71+2+4=7. Another spanning tree is {AC,BC,CD}\{AC, BC, CD\}{AC,BC,CD}, which also connects all four vertices, but has total cost 3+2+5=103 + 2 + 5 = 103+2+5=10.

The minimum spanning tree is

T={AB,BC,BD}T = \{AB, BC, BD\}T={AB,BC,BD}

with total cost 777. We do not include ACACAC, because AAA and CCC are already connected through ABCABCABC at lower cost, and we do not include CDCDCD, because DDD is already connected through BDBDBD at lower cost.

We prove that a minimum spanning tree TTT has no cycles.

Proof

Suppose for contradiction's sake that our minimum spanning tree TTT has a cycle. Deleting any edge eee from the cycle will make the MST cheaper (since all weights are positive). Furthermore, the graph remains connected after deleting an edge (the two endpoints of eee are still connected by the rest of the cycle). This contradicts the minimality of our claimed MST because we have a spanning tree with a lower cost; therefore, a MST cannot contain a cycle.

In the following section, we study Kruskal's and Prim's algorithm to find a graph's minimum spanning tree (MST).

Kruskal's Algorithm​

Kruskal's algorithm builds our spanning tree by greedily selecting the lowest cost edge that does not form a cycle. Suppose that our graph G=(V,E)G = (V, E)G=(V,E) has nnn vertices and mmm edges.

sort all edges based on weight
S = {}, T = {}
while S != V:
    consider edge e = (u, v) with lowest edge weight
    if adding e to T does not create a cycle:
        add u, v to S
        add edge e to T
output T

To implement this into code, we can use a union find data structure; we can easily see if adding an edge will form a cycle by checking if its two endpoints belong to the same connected component. This lets us to process each edge in near O(1)O(1)O(1) time. However, our main bottleneck of our algorithm is the O(mlog⁡m)O(m \log m)O(mlogm) time to sort all edges. Since m≤n2m \le n^2m≤n2, then this turns into O(mlog⁡n)O(m \log n)O(mlogn) overall time complexity.

Prim's Algorithm​

Another strategy for building a MST is to grow it from a root node. Known as Prim's algorithm, we grow the tree outward, greedily selecting the node that can be attached using the least cost edge. Calling our root or starting node sss, here is the pseudocode for Prim's algorithm:

S = {s}, T = {}
while S != V:
    find v not in S such that edge e = (u, v) has minimum weight 
        among all edges with one endpoint in S and other in S \ V
    add v to S
    add e to T
output T

We can implement Prim's algorithm using a min priority queue. We can extract each vertex exactly once from the priority queue, for a time complexity of O(nlog⁡n)O(n \log n)O(nlogn). Additionally, after selecting a node, we need to update the edge costs of all its neighbors (in case there is now a cheaper path to an undiscovered node). We observe that the total number of checks done is bounded by ∑u∈Vdeg⁡(u)=2m\sum_{u \in V} \deg(u) = 2m∑u∈V​deg(u)=2m. So, the total number of potential updates is O(m)O(m)O(m), each costing O(log⁡n)O(\log n)O(logn), giving O(mlog⁡n)O(m \log n)O(mlogn) time complexity for the update step. Since n≤mn \le mn≤m, the overall time complexity is O(mlog⁡n)O(m \log n)O(mlogn).

Cut Property​

When building a MST, we'd like a way to confirm that a particular edge must belong to it (ideally without examining every spanning tree!). This is where the cut property comes in.

Definition: Cut

A cut of a graph G=(V,E)G = (V, E)G=(V,E) is a partition of the vertex set into two nonempty, disjoint sets SSS and V∖SV \setminus SV∖S. An edge e=(u,v)e = (u, v)e=(u,v) crosses the cut if one endpoint lies in SSS and the other lies in V∖SV \setminus SV∖S.

Cut Property. Let (S,V∖S)(S, V \setminus S)(S,V∖S) be any cut of a connected, weighted graph GGG. If eee is an edge of minimum weight among all edges crossing the cut, then there exists a minimum spanning tree of GGG that contains eee. If all edge weights are distinct, this strengthens to: every MST contains eee.

Proof: Let TTT be any MST GGG, and suppose TTT does not contain e=(u,v)e = (u, v)e=(u,v).

  1. Since TTT is a spanning tree, there is a unique path PPP in TTT from uuu to vvv.
  2. Because uuu and vvv lie on opposite sides of the cut, PPP must cross the cut at least once. Let e′e'e′ be an edge of PPP that crosses the cut.
  3. By assumption, ce≤ce′c_e \le c_{e'}ce​≤ce′​, since eee is a minimum-weight crossing edge.
  4. Form T′=T−e′+eT' = T - e' + eT′=T−e′+e. Removing e′e'e′ from TTT splits it into two components; adding eee reconnects them (since eee also crosses the cut), so T′T'T′ is again a spanning tree.
  5. Let w(T)w(T)w(T) be the total edge weight of spanning tree TTT. We have that w(T′)=w(T)−ce′+ce≤w(T)w(T') = w(T) - c_{e'} + c_e \le w(T)w(T′)=w(T)−ce′​+ce​≤w(T)

Since TTT was minimum, w(T′)≥w(T)w(T') \ge w(T)w(T′)≥w(T) as well, so w(T′)=w(T)w(T') = w(T)w(T′)=w(T), meaning T′T'T′ is also an MST, and it contains eee.

To prove the stengthening of our claim, now assume that all edge weights are distinct. Suppose for contradiction's sake that some MST TTT does not contain eee. Consider a similar argument with the path PPP, crossing edge e′≠ee' \ne ee′=e, and the inequality ce≤ce′c_{e} \le c_{e'}ce​≤ce′​ (since eee is the minimum cost edge crossing that cut). Since weights are distinct and e≠e′e \ne e'e=e′, the previous inequality is strict:

ce<ce′\begin{align*} c_{e} < c_{e'} \end{align*}ce​<ce′​​

Consider the exchange of e′e'e′ for eee to produce new tree T′T'T′.

w(T′)=w(T)−ce′+ce<w(T)w(T') = w(T) - c_{e'} + c_{e} < w(T)w(T′)=w(T)−ce′​+ce​<w(T)

so T′T'T′ is a spanning tree with less total edge weight than TTT, contradicting the minimality of TTT. Hence, every MST must contain eee.

Proof of Prim's Algorithm​

Now we prove the correctness of Prim's algorithm using an exchange argument. Let A={e1,e2,…,en−1}A = \{e_1, e_2, \dots, e_{n - 1}\}A={e1​,e2​,…,en−1​} be the edges selected by Prim's algorithm, in the order they were added, and let SkS_kSk​ denote the set of vertices spanned by {e1,…,ek}\{e_1, \dots, e_k\}{e1​,…,ek​} (so S0={s}S_0 = \{s\}S0​={s}). Let OOO be any MST. If A=OA = OA=O, we are done. Otherwise, consider the case A≠OA \ne OA=O.

Since A≠OA \ne OA=O, there is some smallest index kkk such that ek∉Oe_k \notin Oek​∈/O (so e1,…,ek−1∈Oe_1, \dots, e_{k-1} \in Oe1​,…,ek−1​∈O, but ek∉Oe_k \notin Oek​∈/O). Write ek=(u,v)e_k = (u, v)ek​=(u,v) with u∈Sk−1u \in S_{k-1}u∈Sk−1​ and v∉Sk−1v \notin S_{k-1}v∈/Sk−1​; by definition of Prim's algorithm, eke_kek​ is a minimum-weight edge crossing the cut (Sk−1,V∖Sk−1)(S_{k-1}, V \setminus S_{k-1})(Sk−1​,V∖Sk−1​).

Since OOO is a spanning tree, there is a unique path PPP from uuu to vvv in OOO. Since u∈Sk−1u \in S_{k-1}u∈Sk−1​ and v∉Sk−1v \notin S_{k-1}v∈/Sk−1​, PPP must cross the cut (Sk−1,V∖Sk−1)(S_{k-1}, V\setminus S_{k-1})(Sk−1​,V∖Sk−1​) at some edge e′e'e′. Because eke_kek​ is a minimum-weight edge crossing this cut, we have cek≤ce′c_{e_k} \le c_{e'}cek​​≤ce′​.

Note also that e′≠eie' \ne e_ie′=ei​ for any i<ki < ki<k: each eie_iei​ (for i<ki < ki<k) has both endpoints in Sk−1S_{k-1}Sk−1​, so it cannot cross the cut, while e′e'e′ does.

Now form T′=O−e′+ekT' = O - e' + e_kT′=O−e′+ek​. Since e′e'e′ lies on the path between uuu and vvv in OOO, removing it separates uuu from vvv; adding ek=(u,v)e_k = (u,v)ek​=(u,v) back reconnects them, so T′T'T′ is again a spanning tree. Its weight is

w(T′)=w(O)−ce′+cek≤w(O).w(T') = w(O) - c_{e'} + c_{e_k} \le w(O).w(T′)=w(O)−ce′​+cek​​≤w(O).

Since OOO is optimal, w(T′)≥w(O)w(T') \ge w(O)w(T′)≥w(O) as well, so w(T′)=w(O)w(T') = w(O)w(T′)=w(O), meaning T′T'T′ is also an MST. Moreover, since e′≠e1,…,ek−1e' \ne e_1, \dots, e_{k-1}e′=e1​,…,ek−1​, none of these edges were removed, so T′T'T′ contains e1,…,ek−1,eke_1, \dots, e_{k-1}, e_ke1​,…,ek−1​,ek​: one more edge of AAA than OOO did.

We can repeat this process: at each step, we exchange one edge of our current optimal tree for the next edge of AAA it disagrees on, strictly increasing the number of edges shared with AAA while preserving optimality. Since there are only n−1n-1n−1 edges total, this process terminates after at most n−1n-1n−1 exchanges, at which point our tree equals AAA exactly. Since every tree produced along the way is an MST, AAA is an MST.

Problem 1. Suppose we have a undirected graph G=(V,E)G = (V, E)G=(V,E) with edge weights ce>0c_e > 0ce​>0 for each edge e∈Ee \in Ee∈E, and a minimum spanning tree TTT in this graph. Suppose we squared the cost of each edge e∈Ee \in Ee∈E, i.e. let ce′=ce2c'_e = c_e^2ce′​=ce2​. Is TTT still a MST with these new edge weights? If yes, provide a brief explanation; if no, provide a counterexample.

Solution

True. Recall that the MST produced by Kruskal's algorithm depends only on the sorted order of the edge weights. Squaring the weights does not change their relative ordering (since all the weights are positive).

Problem 2. [Task Scheduling] Suppose you have nnn tasks to complete. Task iii takes pi>0p_i > 0pi​>0 time to complete and has priority qi>0q_i > 0qi​>0, representing how costly it is to wait and not do the task. If task iii is completed at time TiT_iTi​, then the total cost is ∑i=1nqiTi\sum_{i = 1}^n q_i T_i∑i=1n​qi​Ti​. Your goal is to decide what order to do the tasks in order to minimize this total.

Consider the following two greedy strategies:

  • Most important task: do tasks in decreasing order of qiq_iqi​.
  • Best value-per-minute: do tasks in decreasing order of the ratio qi/piq_i / p_iqi​/pi​.

Assume all task times, priority values, and ratios are distinct. For both strategies, prove that it gives the optimal schedule or provide a counterexample.

Solution

Most important task. This is not optimal. Consider a scenario with two tasks.

  • Task 1: p1=100p_1 = 100p1​=100, q1=2q_1 = 2q1​=2
  • Task 2: p2=1p_2 = 1p2​=1, q2=1q_2 = 1q2​=1

Using the greedy strategy, we first do task 1. This gives us a total cost of 100⋅2+101⋅1=301100 \cdot 2 + 101 \cdot 1 = 301100⋅2+101⋅1=301. However, if we were to do task 2 first, we would end up with a lower cost of 1⋅1+101⋅2=2031 \cdot 1 + 101 \cdot 2 = 2031⋅1+101⋅2=203. Thus, doing the most important tasks first is not an optimal strategy.

Best value-per-minute. This is optimal. We prove this via an exchange argument. Let the solution produced by our greedy algorithm be AAA, and the optimal ordering be OOO. If A=OA = OA=O, then we are done. Thus, we consider the case where A≠OA \ne OA=O. If A≠OA \ne OA=O, then the optimal ordering differs from the ordering specified by the greedy strategy. This means that there exists two tasks iii and i+1i + 1i+1 in our optimal ordering that do not respect the best value-per-minute ordering, i.e.

qipi<qi+1pi+1\begin{align*} \frac{q_i}{p_i} < \frac{q_{i+1}}{p_{i+1}} \end{align*}pi​qi​​<pi+1​qi+1​​​

Consider swapping the order in which the two tasks are completed. We observe that all the other finish times TjT_jTj​ are the same (so the costs contributed by these other tasks stays the same). However, FiF_iFi​ and Fi+1F_{i + 1}Fi+1​ change.

  • We complete task iii after task i+1i + 1i+1, so FiF_{i}Fi​ increases by pi+1p_{i + 1}pi+1​. The overall cost contributed by task iii increases by qi⋅pi+1q_i \cdot p_{i + 1}qi​⋅pi+1​.

Problem 3. [Tunneling Dilemma] Caleb recently opened a new aquarium with a star attraction orca whale. The orca is showcased in any one of the aquarium's nnn tanks. Lifting the orca out of the water by crane and transporting it from tank to tank is stressful and risky, so Caleb wants it to be able to swim between any two tanks instead.

For any pair of tanks i≠ji \ne ji=j with 1≤i,j≤n1 \le i, j \le n1≤i,j≤n, Caleb can build a tunnel between them at construction cost cij>0c_{ij} > 0cij​>0. The orca can swim through any tunnel he builds, in either direction, and may pass through intermediate tanks on the way. Caleb wants to choose a set of tunnels FFF so that the orca can be moved from any tank to any other tank using only tunnels in FFF, minimizing the total construction cost ∑{i,j}∈Fcij\sum_{\{i, j\} \in F} c_{ij}∑{i,j}∈F​cij​.

Give a polynomial time algorithm that takes as input the costs cijc_{ij}cij​ and outputs a minimum-cost set of tunnels meeting Caleb's requirement.

Hint

Can we represent the problem as a graph? Can we apply one of our MST algorithm to it?

Solution

Let GGG be the complete graph on the nnn tanks with edge weights cijc_{ij}cij​. Run Kruskal's algorithm on GGG and output the resulting tree TTT.

Correctness

Write c(F)=∑{i,j}∈Fcijc(F) = \sum_{\{i,j\} \in F} c_{ij}c(F)=∑{i,j}∈F​cij​, and call FFF feasible if the orca can reach any tank from any other using only tunnels in FFF. Since tunnels are bidirectional and the orca may pass through intermediate tanks, FFF is feasible exactly when (V,F)(V, F)(V,F) is connected.

Claim

Some optimal feasible set is a spanning tree of GGG.

Proof. Feasible sets exist since GGG is complete, so let FFF be optimal. It is connected. Suppose it contained a cycle CCC, and let e={x,y}∈Ce = \{x, y\} \in Ce={x,y}∈C. Then (V,F−e)(V, F - e)(V,F−e) is still connected: any path using eee can be rerouted along the xxx-yyy path C−eC - eC−e, giving a walk and hence a path. So F−eF - eF−e is feasible with

c(F−e)=c(F)−ce<c(F)c(F - e) = c(F) - c_e < c(F)c(F−e)=c(F)−ce​<c(F)

since ce>0c_e > 0ce​>0, contradicting optimality. Thus FFF is connected and acyclic, i.e. a spanning tree. ■\blacksquare■

Every spanning tree is connected and hence feasible, so by the Claim the minimum over feasible sets equals the minimum over spanning trees. Kruskal is correct, so TTT attains the latter, and TTT is feasible. Hence TTT is optimal.
