Stable Matching

Introduction​

Stable matching is a framework for pairing two groups when each participant has ranked preferences over the other side. Classic examples include matching men to women or hospital to residents. We will use hospital and resident example in our notes.

We have hospitals h1,…,hnh_1, \dots, h_nh1​,…,hn​ and residents r1,…,rnr_1, \dots, r_nr1​,…,rn​, each with a ranked preference list over the other side. We want to find a matching MMM (e.g. M={(h1,r16),(h14,r7),… }M = \{(h_1, r_{16}), (h_{14}, r_7), \dots \}M={(h1​,r16​),(h14​,r7​),…}) satisfying two properties:

  • Perfect: All hospitals and residents appear exactly once in our final matching. Intuitively, no one is left unmatched and no one is assigned more than one partner.
  • Stable: There should be no unmatched pair who would both prefer each other over their assigned partners. Formally, there should be no blocking pair: a hospital-resident pair (h,r)∉M(h, r) \notin M(h,r)∈/M where hhh prefers rrr over its current resident r′r'r′ and rrr prefers hhh over its current hospital h′h'h′.

Gale-Shapley Algorithm​

Initialize M = {}
while there is an unmatched hospital h:
    let r = first resident on h's list not yet offered to
    if r is unmatched:
        add (h, r) to M
    else if r prefers h to current match h':
        remove (h', r) from M
        add (h, r) to M
end while
output M

Runtime Analysis​

We observe that no hospital hhh makes an offer twice to any resident rrr. This follows from the description of the algorithm. There are at most n2n^2n2 proposals total. Each iteration of the while loop makes exactly one proposal, the algorithm terminates in O(n2)O(n^2)O(n2) iterations.

We can achieve O(n2)O(n^2)O(n2) runtime with some preprocessing work. For each resident rrr, we create a lookup table rank[r][h] that gives the rank of hhh in rrr's preference list. This takes O(n2)O(n^2)O(n2) time and space to build, and we can compare whether rrr prefers hhh or h′h'h′ by checking rank[r][h] < rank[r][h'] in O(1)O(1)O(1) time. In addition, for each hospital, we maintain a pointer corresponding to the next resident on the list it will propose.

This computation will allow us to process each while loop iteration in O(1)O(1)O(1) time. We take O(n2)O(n^2)O(n2) time for setup, and O(1)O(1)O(1) time for O(n2)O(n^2)O(n2) possible proposals. Thus, our overall time complexity is O(n2)O(n^2)O(n2).

Correctness​

We prove that Gale-Shapley produces a stable perfect matching. We show each of these properties separately; try them yourself before reading the solutions!

Claim 1: The output is a perfect matching.

Hint

Suppose we don't have a perfect matching. If hhh is unmatched at termination, what can you say about every resident on hhh's preference list?

Proof

We first observe that if a resident rrr is matched at some step of Gale-Shapley, it remains matched (assuming hospitals are proposing). This follows from the fact that if resident rrr is matched to some hospital hhh at some point, it can only leave hhh for a higher ranked h′h'h′.

Suppose by contradiction that some hhh is unmatched at the end of G-S. This means that some resident rrr is also unmatched. Since hhh is unmatched at termination, it was never permanently accepted by an resident, meaning that it was rejected by every resident it offered to. Since the algorithm only terminates when no unmatched hospital has a resident left to offer to, hhh must have exhausted its entire preference list. In particular, hhh must have offered to rrr at some point during the algorithm.

  • Case 1: rrr was unmatched, and hhh makes an offer to rrr. Then, (h,r)(h, r)(h,r) becomes a pair in our matching. By our prior reasoning, once rrr is matched, it remains matched until the end of G-S. This is a contradiction, since we assumed rrr was unmatched at the end.
  • Case 2: rrr is matched to some h′h'h′, and hhh makes an offer to rrr. We observe that rrr cannot be unmatched (because it must stay with h′h'h′ or be matched with hhh), so this is a contradiction again.

Therefore, all hhh are matched, so we have a perfect matching. □\square□

Claim 2: The output is stable.

Hint

Recall what it means for a pair (h,r)∉M(h, r) \notin M(h,r)∈/M to be a blocking pair. Argue by contradiction why no such pair can exist in the output of Gale-Shapley!

Proof

Suppose for contradiction's sake that MMM is not stable. Then, there exists some pair (h,r)∉M(h, r) \notin M(h,r)∈/M such that (h,r′),(h′,r)∈M(h, r'), (h', r) \in M(h,r′),(h′,r)∈M with h>h′h > h'h>h′ in rrr's preference list and r>r′r > r'r>r′ in hhh's preference list.

We first observe that hhh must have made an offer to rrr, since (h,r′)(h, r')(h,r′) is a pair and r>r′r > r'r>r′ in hhh's preference list. When hhh made an offer to rrr, two things could have happened:

  • rrr is unmatched. Then, (h,r)(h, r)(h,r) are matched. If (h′,r)(h', r)(h′,r) is in the final matching, this implies that h′>hh' > hh′>h in rrr's preference list (this is the only way that rrr unmatches from hhh and matches with h′h'h′). This is a contradiction, because we assumed h>h′h > h'h>h′ in rrr's preference list.
  • rrr is matched (when hhh offers to rrr). Suppose that rrr is matched to some h2h_2h2​. If r:h>h2r: h > h_2r:h>h2​, rrr leaves h2h_2h2​ for hhh and (h,r)(h, r)(h,r) becomes a pair. This return the situation described above, which we know leads to a contradiction. Thus, we assume rrr rejects hhh and stays with h2h_2h2​. This means that h2>h>h′h_2 > h > h'h2​>h>h′ in rrr's preference list by transitivity. But rrr is matched to h2h_2h2​ (or some other hospital that rrr prefers even more) and would never downgrade to h′h'h′, contradicting that (h′,r)∈M(h', r) \in M(h′,r)∈M.

Therefore, we have no unstable pairs, and Gale-Shapley outputs a stable matching. □\square□
